# Lab 4 Steering Log

### Incident 1: Unsafe Cancel and Missing Status Rules

- **Initial Agent Output:** I gave the agent a short prompt asking for cancel, an availability filter, a user bookings list and double booking prevention. It added `PATCH /reservations/:id/cancel`, but the service just called `findByIdAndUpdate` and set the status to `CANCELLED` without checking the current status. Cancelling the same reservation twice returned 200 both times, and the agent's own comment called that a no-op. A reservation id that didn't exist came back as 400 because it reused `ValidationError` for not found. There was no way to move a reservation to `CONFIRMED` at all. The agent still reported that every case in its smoke test passed, since it only tested the happy path.
- **Root Cause:** My prompt didn't include the Part 1 state rules (which statuses can move to `CANCELLED` or `CONFIRMED`), so the agent had nothing to check the transition against. It also only had the Lab 3 `CLAUDE.md`, which lists `ValidationError` and `DoubleBookingError` as the only service errors, so it forced not found into `ValidationError` instead of adding a new error type.
- **Remediation Prompt:**
  > cancel isn't safe, cancelling twice gives 200 and a missing id gives 400. only pending or confirmed can be cancelled, only pending can be confirmed, add a confirm endpoint. bad id 400, not found 404, wrong status 409. add new error classes in services/errors.ts for these.
- **Resolution:** The fixed service puts the allowed current statuses inside the update query, so a reservation that's already cancelled doesn't match and the request gets a 409. If nothing matches, it looks the id up to tell 404 apart from 409. I checked it with curl against a seeded MongoDB: cancelling twice gave 200 then 409, confirming a pending reservation gave 200, confirming a cancelled one gave 409, id `abc` gave 400, and an unknown id gave 404. Rebooking the same slot after cancelling gave 201, so cancel still frees the slot. I also reran the earlier Lab 2 and Lab 3 checks (resources, double booking 409, validation 400s) with no regressions, and `npm run typecheck` and `npm run lint` pass.
